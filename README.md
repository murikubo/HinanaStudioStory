# Hinana Studio Story

Windows와 macOS용 Electron 비주얼 노벨 제작기입니다. React + TypeScript + Vite로 편집기와 작품 재생기를 구성합니다.
현재 버전: **0.6.0**.

## 시작하기

Node.js 24 LTS에서 다음 명령을 실행합니다.

```sh
npm ci
npm run dev
```

화면만 확인하려면 `npm run dev:web`을 실행하고 http://127.0.0.1:5173 에 접속합니다.
웹 미리보기에서는 프로젝트 다운로드를 지원하고, 작품 배포 기능은 Electron 데스크톱 앱에서 사용합니다.

## 제작 기능

- 장면 추가·삭제·이름 변경, 대사·내레이션·선택지 블록 편집·복제·삭제
- PNG/JPG/WebP 배경·캐릭터·표정 이미지 불러오기 (개별 8MB)
- 캐릭터 라이브러리: 이름·이름표 색상·여러 표정 등록, 등록 화자 선택 및 말하는 인물 강조
- 여러 캐릭터 동시 배치: 위치(좌/중/우), 크기(30–120%), 앞뒤 순서(0–99), 블록별 배치·표정·숨기기
- 에셋 관리: 연결을 유지하는 교체, 미사용 정리, 투명도를 유지하는 WebP 개별/일괄 압축
- 단일 파일 또는 외부 에셋 폴더 방식 선택, IndexedDB 기반 대용량 자동 복구
- MP3/WAV/OGG/WebM 음악 불러오기 (개별 20MB), 장면별 BGM·볼륨·반복·페이드
- 블록별 효과음·볼륨
- 장면 전환 및 캐릭터 등장·퇴장의 페이드·슬라이드, 전환 시간 설정
- 숫자 변수 초기값, 블록 진입 시 더하기·대입, 조건부 선택지
- 장면 미리보기와 실제 재생기를 사용하는 플레이 테스트
- 최대 40단계 실행 취소·다시 실행 (Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z, Windows Ctrl+Y), `.hinanastory` JSON 저장·열기 (기존 `.hinana`·`.json` 열기 호환)
- 로컬 자동 복구, 프로그램 정보 창
- 기본 SVG 교실 배경과 분기 예제 (외부 이미지·폰트 요청 없음)

이미지를 포함한 프로젝트 파일의 최대 크기는 80MB입니다. 로컬 자동 복구 저장 공간은 그보다 작을 수 있습니다.
자동 복구 공간이 부족하면 하단 상태에 표시됩니다. 프로젝트 파일 저장(Ctrl/Cmd+S)을 함께 사용하세요.
이전 버전 프로젝트도 열 수 있으며 새 기능은 선택 필드로 저장됩니다.

### 캐릭터·음악·연출

장면 속성에서 기본 캐릭터 이미지를 선택하고 **캐릭터 연출 · 배경 음악**을 펼쳐 위치·크기·BGM·전환을 설정합니다.
대사/선택지 블록의 **블록별 캐릭터 연출**에서 표정 이미지·위치·숨기기와 효과음을 지정합니다.
블록 설정은 해당 블록에만 적용되며 다음 블록은 장면 기본 설정을 따릅니다.
투명 PNG/WebP는 캐릭터에 적합합니다. 음악은 에셋 탭에서도 들어볼 수 있습니다.
같은 BGM을 사용하는 장면에서는 음악이 이어지고, 다른 BGM 또는 BGM 없는 장면에서는 페이드 설정에 따라 전환합니다.
오디오 코덱 지원은 실행 환경에 따릅니다.

### 변수·조건

왼쪽 **변수** 탭에서 숫자 변수와 초기값을 만듭니다.
블록 속성의 **변수 변경 추가**로 진입 시 더하기(음수 가능) 또는 대입을 설정합니다.
선택지 **표시 조건**에서 `==`, `!=`, `>`, `>=`, `<`, `<=` 비교를 지정합니다.
조건을 지정하지 않은 선택지는 항상 표시됩니다. 만족하는 조건이 없으면 종료 안내를 표시합니다.
변수 삭제 시 연결된 변경 작업과 조건도 제거됩니다. 실행 취소로 복원할 수 있습니다.
장면 마지막 대사는 다음 연결이 없으면 이야기를 마치며, 다음 연결 또는 선택지로 다른 장면에 이어질 수 있습니다.

## 프로젝트·장면·블록 관리 (v0.5.0)

상단 **프로젝트** 메뉴에서 새 프로젝트, 다른 이름으로 저장, 최근 프로젝트(최대 10개)를 사용할 수 있습니다.
데스크톱 앱은 마지막으로 열거나 저장한 경로를 기억하며 이후 **저장**은 해당 파일을 갱신합니다.
자동 복구한 프로젝트는 이전 경로가 최근 목록에 남아 있으면 앱 재실행 후에도 그 경로에 저장할 수 있습니다.
새 프로젝트는 빈 장면으로 시작합니다. 다른 프로젝트로 이동할 때 미저장 변경이 있으면 저장·계속·취소를 선택합니다.
최근 파일이 이동·삭제되었거나 형식 검증에 실패하면 현재 프로젝트와 저장 경로를 유지합니다.
최근 파일 경로 기억은 Electron 데스크톱 앱에서 지원하며 웹 미리보기는 다운로드 방식으로 저장합니다.

새 파일 확장자는 **`.hinanastory`**입니다. 기존 `.hinana` 및 `.json` 프로젝트도 열 수 있습니다.
이전 확장자 파일을 열어 저장하면 새 `.hinanastory` 경로를 선택하게 되며 기존 파일은 유지됩니다.
내부 프로젝트 데이터는 버전 1 JSON 형식을 유지하므로 기존 에셋·변수·분기 설정도 호환됩니다.

- 장면 목록에서 드래그하거나 속성의 위/아래 버튼으로 순서를 바꿉니다.
- 시작 장면은 순서와 별도로 지정할 수 있습니다. 순서를 바꿔도 원래 시작 장면을 유지합니다.
- 블록 옆 체크박스로 여러 개를 선택하고 위/아래 이동, 복사·붙여넣기, 삭제를 실행합니다.
- 대상 장면을 고른 뒤 **이동** 또는 **장면에 복사**를 사용합니다.
- 블록을 다른 블록 위로 드래그하면 그 앞에 놓고, 장면 목록에 드롭하면 해당 장면 끝으로 이동합니다.
- 복사한 블록과 선택지는 새 ID를 받습니다. 모든 블록을 옮기거나 지우면 빈 블록 하나를 남깁니다.
- 장면 삭제 전 대상 이름과 블록 수를 확인합니다. 삭제 후 인접 장면을 선택하며, 실행 취소하면 장면·연결과 이전 장면/블록 선택을 함께 복원합니다. 마지막 한 장면은 삭제할 수 없습니다.
- 복사·이동·순서 변경은 실행 취소할 수 있습니다. 새 프로젝트나 파일 열기는 편집 이력을 초기화합니다.

### 연결 그래프·검사

왼쪽 **연결** 탭에서 장면 연결 그래프를 열 수 있습니다.
노드를 선택하면 오른쪽 속성을 편집하고, **선택 장면 편집**으로 대사 편집으로 돌아갑니다.
보라색은 선택지 분기, 초록색은 장면 끝의 다음 연결입니다. 선택 장면의 연결 목록에서 대상 장면을 열 수 있습니다.

장면 속성의 **장면 끝의 다음 연결**을 지정하면 마지막 대사에서 다음 장면으로 이어집니다.
비워두면 이야기가 끝납니다. 선택지는 먼저 지정한 대상으로 이동하므로 같은 장면 뒤쪽 블록이나 기본 다음 연결을 실행하지 않습니다.

검사는 도달 불가 장면, 빈 선택지, 잘못된 연결, 선택지 뒤 실행되지 않는 블록,
모든 선택지가 조건부인 경우, 사용되지 않는 다음 연결, 연결된 종료 장면이 없는 경우를 표시합니다.
진행을 막는 오류가 있으면 작품 내보내기를 비활성화합니다. 경고는 검토 후 내보낼 수 있습니다.
변수 조건이 실제로 충족되는지는 플레이 테스트로 확인하세요.

## 작품 재생기

편집기의 플레이 테스트와 내보낸 게임이 동일한 재생기를 사용합니다.

- 타이핑 효과와 텍스트 속도 조절 (0이면 즉시 표시)
- 클릭·Enter·Space: 대사 표시 중에는 전체 표시, 표시가 끝나면 다음 대사
- 자동 진행: 대사를 모두 표시한 후 설정한 시간만큼 기다려 진행
- 읽은 대사 스킵: 이미 읽은 대사만 빠르게 진행, 새 대사와 선택지에서는 멈춤
- 대사 기록 (최근 500개 블록)
- 수동 슬롯 6개, 자동 저장, 퀵세이브·퀵로드 (F5/F9)
- 음악·효과음 음량, 음소거, 자동 진행 대기 시간 설정
- 제목 화면의 처음부터 시작·이어하기·불러오기·설정, 엔딩 화면

선택지를 자동으로 고르지 않습니다. 플레이 테스트에서 Esc는 편집기로 돌아가고, 배포 게임에서는 설정을 엽니다.
플레이 테스트 하단에는 변수 값이 표시됩니다. 배포 게임에서는 표시되지 않습니다.

### 저장 방식

플레이 저장은 제작 프로젝트 파일과 별개이며 이 기기의 로컬 저장소에 보관됩니다.
테스트 플레이와 배포 게임은 저장 공간을 구분합니다. 배포 게임의 Windows 버전은 작품마다 독립된 사용자 데이터 폴더를 사용합니다.
장면·블록 위치·변수 값·대사 기록을 저장하며 불러올 때 블록의 변수 변경이나 효과음을 다시 실행하지 않습니다.
새 게임은 변수를 초기화하고, 이어하기/불러오기는 저장된 값을 복원합니다. 읽은 대사 표시는 새 게임에서도 유지됩니다.
작품 구조·대사·변수 설정이 바뀌면 호환되지 않는 슬롯과 읽음 표시는 무효화합니다.
웹에서는 같은 브라우저·주소를 사용해야 기존 저장을 찾을 수 있습니다. 브라우저 데이터 삭제는 플레이 저장도 삭제합니다.

## 작품 내보내기

상단 **작품 내보내기**를 누르고 형식과 출력 위치를 선택합니다. 기존 폴더를 덮어쓰지 않고 새 폴더를 만듭니다.
제목 화면의 작품명은 프로젝트 이름을 사용합니다.

### Windows 게임

Windows x64 `.exe`, Electron 런타임, 작품 파일을 포함하는 **실행 가능한 배포 폴더**를 생성합니다.
대상 Windows 컴퓨터에 Node.js나 제작기를 설치할 필요가 없습니다.
처음에는 공식 Electron 런타임을 다운로드하고 체크섬을 검증하므로 인터넷 연결이 필요합니다. 다운로드는 캐시됩니다.
전체 폴더를 전달하고 그 안의 `<작품명>.exe`를 실행합니다. 실행 파일 하나만 전달하면 동작하지 않습니다.
배포 형식에서 실행 폴더, NSIS 설치 프로그램, 설치 없이 실행하는 단일 EXE를 선택할 수 있습니다. 인증서가 없으면 미서명 빌드로 생성합니다.
작품 설정의 아이콘·제작자·버전·설명을 실행 파일 리소스에 반영합니다. 창 제목과 파일명은 작품명을 사용합니다.
패키징 방법: [Electron 공식 배포 문서](https://github.com/electron/electron/blob/main/docs/tutorial/application-distribution.md).

### 웹 게임

재생기·작품·에셋을 포함하는 정적 웹 폴더를 생성합니다. 정적 웹 호스팅에 올려 실행합니다.
로컬 확인은 출력 폴더에서 `python3 -m http.server 8080`을 실행한 뒤 http://localhost:8080 에 접속합니다.
HTML 파일을 더블클릭하는 방식은 작품 파일 로딩이 제한될 수 있습니다.

## 제작기 빌드와 검증

```sh
npm run build           # 타입 검사 + 편집기/재생기 프로덕션 빌드
npm test                # 모델·저장·조건·메타데이터·입출력 테스트
npm run pack            # 현재 OS의 제작기 앱 폴더
npm run dist            # 현재 OS의 제작기 설치 패키지
npm run dist:win        # 제작기 Windows x64 NSIS 설치 프로그램
```

제작기 Windows 설치 파일은 Windows에서 `npm ci` 후 `npm run dist:win`으로 빌드하는 경로를 권장합니다.
`.github/workflows/build.yml`은 수동 실행 또는 `v*` 태그 push로 Windows/macOS에서 각각 빌드해 설치 파일을 보관합니다.
출력 위치는 `release/`이며 서명 인증서는 연결하지 않았습니다.

개발 서버를 실행한 상태에서:

```sh
npx playwright install chromium
npm run test:ui         # 편집·이미지·음악·변수·정보 창·창 크기 회귀 확인
npm run test:game       # 샘플 웹/Windows 작품 내보내기 + 웹 재생기 통합 확인
node scripts/smoke-projects.mjs  # 최근 파일/저장 경로/새 프로젝트/이전 확장자 확인
node scripts/smoke-electron.mjs  # 네이티브 파일 입출력 확인
node scripts/smoke-export.mjs    # Electron 내보내기 UI + 내보낸 작품의 macOS Electron 실행
```

`test:game`은 Windows 런타임을 처음 다운로드할 수 있습니다.
`scripts/smoke-export.mjs`는 `test-results/exports/` 폴더가 있어야 합니다 (`test:game`에서 생성).
`ELECTRON_BINARY` 환경변수에 패키징한 제작기 실행 파일을 지정하면 해당 앱을 테스트합니다.
샘플 결과와 화면 캡처는 `test-results/`에 생성됩니다.

## 구조

- `src/model.ts`: 프로젝트 스키마, 검증, 조건·재생 순서와 일괄 편집
- `src/flow.ts`, `src/SceneGraph.tsx`: 연결 분석·도달성 검사·그래프
- `src/BlockTools.tsx`, `src/ProjectMenu.tsx`: 일괄 편집과 프로젝트 관리
- `electron/project-files.cjs`: 저장 경로·최근 파일·확장자 마이그레이션
- `src/player-store.ts`: 플레이 저장 스키마, 프로젝트 호환성, 설정
- `src/Player.tsx`: 타이핑·기록·조작·제목 화면·저장 UI
- `src/PlayerStage.tsx`, `src/PlayerAudio.tsx`: 장면·캐릭터 전환과 오디오
- `src/game.tsx`, `game.html`: 배포 게임 진입점
- `src/App.tsx`, `src/Controls.tsx`: 편집 상태와 속성 UI
- `src/ExportGame.tsx`: 작품 내보내기 UI
- `electron/exporter.cjs`, `electron/unzip.cjs`: 웹/Windows 작품 생성과 압축 해제
- `electron/game-main.cjs`, `electron/game-preload.cjs`: 배포 게임의 제한된 데스크톱 런타임
- `electron/main.cjs`, `electron/preload.cjs`: 제작기 창과 파일·내보내기 IPC
- `src/About.tsx`, `src/metadata.ts`: 프로그램 정보 (버전은 package.json 참조)

Electron은 `contextIsolation`, `sandbox`를 활성화하고 Node 통합을 비활성화합니다.
IPC main frame을 확인하고 새 창과 페이지 이동을 차단합니다.
배포 게임에는 편집기의 파일 저장·열기·내보내기 API가 노출되지 않습니다.

## 검증 범위와 후속 확장

타입 검사, 모델/저장 테스트, 편집기·레이아웃·웹 재생기 통합 확인, macOS 제작기 패키징 및 네이티브 파일 입출력을 확인합니다.

## 캐릭터와 에셋 사용법 (0.5.0)

왼쪽 **캐릭터** 메뉴에서 인물을 만들고 이미지를 표정으로 연결합니다. 오른쪽 장면 설정의 **등장 캐릭터**를 펼쳐 등록 배치를 활성화하고 인물을 추가합니다. 기본 표정·위치·크기·레이어·표시 여부를 설정하고, 대사의 **등록 화자**를 선택하면 이름과 이름표 색상이 자동 적용되고 다른 인물은 어둡게 표시됩니다.

**블록 캐릭터**에서 장면 배치를 복사해 해당 블록의 표정과 배치를 덮어쓸 수 있습니다. **이 블록에서 따로 배치**로 블록 전용 배치를 만들고, **장면 설정으로 되돌리기**로 장면 배치를 이어받습니다. 장면의 **단일 이미지로 전환**은 등록 배치를 해제하고 저장된 단일 이미지 설정을 사용합니다. 기존 프로젝트는 등록 배치를 켜기 전까지 기존 단일 캐릭터 설정으로 재생됩니다. 등록 캐릭터의 이름 변경은 연결된 화자 표시에도 반영됩니다. 캐릭터·표정 삭제 시 관련 배치는 정리되고 실행 취소로 복구할 수 있습니다.

**에셋 → 프로젝트 저장 방식 → 외부 에셋 폴더**를 선택하고 저장하면 `작품.hinanastory`와 `작품.assets/`가 만들어집니다. 이동·공유할 때 파일과 폴더를 함께 복사해 주세요. 불러올 때 에셋이 빠져 있으면 오류를 알리고 현재 프로젝트를 유지합니다. 다른 이름으로 저장하면 새 파일에 맞는 에셋 폴더가 생성됩니다. 단일 파일 방식으로 바꾸고 저장하면 다시 모든 에셋을 포함합니다. 작품 내보내기는 어느 저장 방식이든 필요한 에셋을 포함합니다.

미사용 정리는 **프로젝트에서** 에셋을 제거합니다. 외부 폴더의 기존 파일은 이전 저장본 보호를 위해 자동 삭제하지 않습니다. 교체는 에셋 ID와 연결을 보존하며, 사용 중인 에셋의 개별 삭제는 막습니다. 압축은 선택한 최대 크기와 WebP 품질을 적용하며 더 작아질 때만 교체합니다. 자동 복구는 기기 내 IndexedDB를 사용하며 정식 프로젝트 파일 저장과 별개입니다.

추가 검증: `node scripts/smoke-library.mjs` (캐릭터/에셋/16MB 복구), `node scripts/smoke-external.mjs` (Electron 외부 폴더 저장·열기·변환). 모델/파일 테스트는 총 29개입니다.

## 프로젝트 사본 저장과 종료

**프로젝트 → 새 프로젝트로 저장**에서 새 이름을 지정하면 현재 장면·대사·캐릭터·에셋을 별도 `.hinanastory`로 저장하고 사본에서 작업을 이어갑니다. 원본 파일을 선택하면 덮어쓰기를 막으며, 사본은 고유 프로젝트 ID를 받아 플레이 저장 데이터도 분리됩니다. **다른 이름으로 저장**은 기존 프로젝트의 저장 위치를 바꾸는 용도로 유지됩니다.

데스크톱 앱의 **프로젝트 → 종료**, 창 닫기, Windows Alt+F4, macOS 앱 종료 요청은 저장하지 않은 내용이 있으면 **저장하고 종료 / 저장하지 않고 종료 / 취소**를 표시합니다. 저장 취소나 실패 시 앱이 열린 상태를 유지합니다. **저장하지 않고 종료**는 변경된 자동 복구본도 정리하므로 다음 실행 때 버린 편집 내용이 되살아나지 않습니다. 마지막 저장 파일과 플레이 저장 데이터는 유지됩니다.

검증: `node scripts/smoke-file-actions.mjs` (사본·원본 보호, 종료 취소/저장/버리기, 저장 취소·실패, 재실행 후 복구 확인). 모델/파일 테스트는 총 29개입니다.

## macOS 게임 내보내기

Mac 제작기에서 **작품 내보내기 → macOS 게임 → 폴더 선택 후 내보내기**를 선택합니다. 완료 후 **게임 실행**으로 독립 게임 클라이언트를 열거나 **내보낸 폴더 열기**로 Finder에서 확인합니다. Windows 내보내기는 Windows에서 게임 실행 버튼이 활성화됩니다. 웹 게임은 정적 서버에서 실행합니다.

현재 실행 중인 제작기 CPU에 맞춰 Apple Silicon(arm64) 또는 Intel(x64)용 `.app`을 만듭니다. Mac 대상은 Mac에서 내보냅니다. 검증된 Electron 런타임을 처음 다운로드할 때 인터넷 연결이 필요합니다. macOS 앱에는 이야기·이미지·음악·엔딩 로고와 재생기가 모두 포함되므로 앱만 다른 폴더로 옮겨도 실행할 수 있습니다. 제작기나 개발 서버는 필요하지 않습니다.

앱 이름과 식별자를 작품에 맞게 설정하고, 로컬 테스트를 위한 ad-hoc 서명을 적용·검증합니다. Developer ID 배포 서명·Apple 공증·Universal 바이너리는 포함하지 않습니다. 플레이 데이터는 프로젝트별 사용자 Application Support 경로에 보관되어 재실행 후에도 유지됩니다. 실행 및 폴더 열기는 현재 제작기에서 성공적으로 내보낸 결과에만 허용합니다.

`npm run test:mac`은 기존 웹·Windows 배포 검증 후 실제 macOS `.app` 내보내기 UI와 게임 실행 버튼, 다른 폴더로 옮긴 앱 실행, 음악·캐릭터·조건부 분기·슬롯·퀵세이브·엔딩 로고·재실행 복원을 확인합니다. `ELECTRON_BINARY`로 패키징한 제작기를 지정할 수도 있습니다. 모델/파일/실행 경로 테스트는 총 29개입니다.

5분 예제의 Mac 앱 생성: `node examples/last-broadcast/export-mac.mjs`. 생성 위치는 `release/games/`이며 실제 경로를 `test-results/last-broadcast-macos-export.json`에도 기록합니다.

## 0.6.0 제작·저장·배포 완성 기능

### 작품 설정

왼쪽 **작품** 메뉴에서 제작자, 버전(`1.2.3` 형식), 설명, 저작권, 정사각형 작품 아이콘, 제목 화면의 부제·배경·테마 색상, 엔딩 인사말·제작자 로고·추가 크레딧을 지정합니다. 이미지는 프로젝트에 포함되고 에셋 정리 시 사용 중인 것으로 보호합니다. 원래 프로젝트는 설정 없이 기존 화면으로 열립니다. `Powered by Hinana Studio Story`는 계속 표시됩니다.

### 플레이 저장 파일

수동·자동·퀵세이브 슬롯에 장면과 캐릭터, 대사가 포함된 썸네일을 표시합니다. 저장 창과 불러오기 창에서 `.hinanasave`로 전체 슬롯·읽음 기록을 내보내거나 가져올 수 있고, 개별 슬롯을 삭제할 수 있습니다. 데스크톱은 네이티브 파일 대화상자, 웹은 다운로드·파일 선택을 사용합니다. 가져오기 전에 같은 번호 슬롯의 교체를 확인하며 다른 작품이나 변경되어 호환되지 않는 작품의 저장은 거부합니다. 가져오기가 현재 재생 위치나 변수 변경 작업을 실행하지 않습니다. 프로젝트 `.hinanastory`와 플레이 저장 `.hinanasave`는 별도 형식입니다.

### 배포 형식

- macOS: 독립 `.app`, `.zip`, Applications 바로가기를 포함하는 `.dmg`
- Windows: 전체 실행 폴더, 설치 위치를 선택할 수 있는 NSIS 설치 EXE, 런타임을 포함하는 Portable 단일 EXE
- 웹: 정적 웹 폴더

Windows 단일 EXE는 실행 시 런타임을 임시 폴더에 풀어 사용합니다. 사용자 데이터는 앱 파일과 별도로 유지됩니다. Mac ZIP과 DMG를 만들 때도 테스트 가능한 원본 `.app`을 결과 폴더에 남깁니다. 내보내기 완료 창에서 생성된 배포 파일명을 확인할 수 있습니다. Mac 앱은 현재 제작기 CPU와 같은 아키텍처이며, Windows 실행 검증은 Windows 기기에서 추가로 수행해야 합니다. 패키징 도구의 첫 다운로드에는 인터넷 연결이 필요합니다. 배포 패키지는 항상 새 폴더에 생성합니다.

### 인증서 연결 (선택)

인증서가 없을 때 Mac은 로컬 실행용 ad-hoc 서명, Windows는 미서명으로 빌드합니다. 인증서 정보와 비밀번호는 프로젝트에 저장하지 않습니다.

- Mac: 키체인에 설치한 Developer ID 이름 또는 SHA-1을 `HINANA_MAC_SIGN_IDENTITY` 환경 변수로 지정한 뒤 제작기를 실행합니다. 내보내기의 **코드 서명 → 설정된 배포 인증서 사용**을 선택하면 해당 인증서로 서명합니다. Apple 공증 제출은 자동 실행하지 않습니다.
- Windows: Windows에서 `CSC_LINK`와 `CSC_KEY_PASSWORD`를 설정한 뒤 제작기를 실행합니다. 설치형·Portable 빌드의 인증서 서명 옵션이 활성화됩니다. 인증서 환경이 없는데 배포 서명을 요청하면 미서명으로 조용히 대체하지 않고 오류를 표시합니다.

현재 인증서가 없는 환경이므로 인증서 서명 자체는 검증하지 않았습니다. 로컬 서명과 생성된 패키지는 검증합니다.

추가 확인 명령:

```sh
node scripts/smoke-completion.mjs     # 작품 설정·썸네일·저장 파일 UI (dev:web 필요)
node scripts/smoke-distribution.mjs   # 앞 테스트의 completion.hinanastory로 모든 배포 형식 검증
```

Mac 검증은 ZIP 추출 후 서명 검사, DMG 검증·읽기 전용 마운트, DMG 안 앱 실행과 네이티브 저장 파일 입출력을 포함합니다. 결과는 `test-results/distributions.json`에 기록합니다.

현재 편집 중인 블록을 바로 확인하려면 미리보기 위의 **현재 위치에서 테스트** 또는 **Ctrl/Cmd+Enter**를 사용하세요. 선택한 블록부터 재생하고, 닫으면 편집 위치로 돌아옵니다. 변수는 초기값에서 시작해 현재 장면의 앞선 블록과 시작 블록의 변경 작업을 반영합니다. 이전 장면의 분기 결과는 재현하지 않습니다. 상단 **플레이 테스트**는 기존처럼 현재 장면 첫 블록에서 시작합니다.

엔딩은 마지막 장면의 배경과 음악을 유지하는 전용 화면으로 표시됩니다. 제작자 로고 → 역할별 제작진 → Hinana Studio Story → 감사 인사 순서로 크레딧이 자동 스크롤되며 일시정지·처음부터·끝으로 이동을 지원합니다. 직접 스크롤하면 자동 진행이 멈춥니다. 동작 줄이기 설정에서는 수동으로 시작합니다. 작품 설정의 **엔딩 미리보기**로 확인할 수 있으며, 추가 크레딧은 `시나리오 · 이름` 또는 `음악: 이름`처럼 한 줄씩 작성하세요. 제목 화면으로 돌아가면 음악이 멈춥니다.

이미지·음악 파일을 편집기나 에셋 화면으로 끌어다 놓으면 여러 파일을 함께 추가할 수 있습니다. 파일 선택창에서도 다중 선택을 지원합니다. 이미지당 8MB, 음악당 20MB, 프로젝트 전체 80MB 한도를 적용하며 지원하지 않는 파일은 이유를 표시하고 제외합니다. 한 번에 추가한 에셋은 한 번의 실행 취소로 복원할 수 있습니다.

장면 미리보기의 **캐릭터 수동 배치**를 켜고 캐릭터를 드래그하거나 X/Y 좌표를 입력하세요. **현재 블록만**은 해당 블록에 배치를 복사해 독립적으로 조절하고, **장면 기본 배치**는 기본 위치를 수정합니다. 좌표는 화면 왼쪽 위를 기준으로 캐릭터의 하단 중앙을 백분율로 나타냅니다. 드래그 한 번을 실행 취소 한 단계로 처리하며, Esc로 드래그를 취소하거나 기본 위치 복원 버튼으로 왼쪽/가운데/오른쪽 배치로 돌아갈 수 있습니다. 기존 단일 이미지 캐릭터와 여러 등록 캐릭터 모두 지원하며, 저장·내보내기·플레이·저장 썸네일에 같은 좌표가 적용됩니다.

캐릭터 속성은 현재 사용하는 방식에 맞게 표시됩니다. 등록 캐릭터 배치를 사용하면 적용되지 않는 단일 이미지·위치·표정 설정은 숨깁니다. 드래그하거나 좌표를 지정하면 위치 메뉴에도 **수동 배치**로 표시되며, 왼쪽/가운데/오른쪽을 선택하면 같은 좌표를 기본 위치로 되돌립니다.
